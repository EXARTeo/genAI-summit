## The product: AI Act Governance Copilot (design 2026-11-14)

Read first: [docs/architecture/README.md](docs/architecture/README.md) (summary + diagrams), [docs/architecture/agent-context.md](docs/architecture/agent-context.md) (context, plugins, memory, filesystem), full design PDF in Greek: `docs/architecture/ai-act-governance-copilot.pdf` (its §12 is the MVP and overrides §9 / §11.5).

- **What:** an agentic EU AI Act compliance assistant run in-house. **MVP = AI Engineer pillar only, for high-risk systems the org builds as provider.** Risk class and system card are seeded (as if PM + AI Officer made them). Given a system + its model(s), the agent derives the applicable requirements, plans tests, generates auditable synthetic data, runs tests in the sandbox, and returns findings with reasoning **and** counter-arguments, plus an engineer report and a management report. When the law/guidelines change it finds affected systems and re-runs what's needed.
- **Roles (three pillars, no login):** AI Officer (oversees all systems, audits, findings register, regulation changes; today the shared read view), PM (registers a system with **docs only: no pipeline, no models**; **built 2026-11-15 (plan 02)**: Register wizard `/systems/new`; risk-classification agent = its own package `mnamon/agents/classification/` (separate from the audit pipeline `pipeline/`): code pre-checks → one Gemini step with regulation tools → code verifier (1 redo; limited risk only for declared Art. 50 features) → Oumi Iris independent check (no Gemini self-grading) → Omnibus dates; backend `router/utils/schema classifications.py`, migration 0008 (append-only events), statuses running→proposed|failed→approved|rejected→stale|superseded, approve writes `system-card.yaml`; Overview risk card with Approve / Reject; `GET /v1/systems/{id}/obligations` preview; docs `docs/services/agents-classification.md`), AI Engineer (**builds the system graph and one plugin per model in the Plugins tab**, runs audits; **the only pillar built**). An audit tests one plugin (`data.target_plugin`, else the decision model).
- **Principles:** human-in-the-loop (agents write `proposed`, humans make `approved`); every claim cites a source; deterministic skeleton (code/YAML rules), LLM only for judgement; every finding locks `kb_version`; fairness thresholds are the org's, not the law's (say so in findings).
- **Containers:** existing `backend` (API, cards, runs, findings, webhooks, Telegram) and `agents` (LangGraph test + impact pipelines), `sandbox` (no network except target + MLflow), Postgres, Redis, Langfuse (trace = audit trail); new `frontend` (Vite + React engineer workspace), `reg-memory` / RKS (all regulation, versioned YAML corpus in git, watcher, diff, change judge), `mlflow` (models + test runs).
- **Engineer pipeline:** `load_context → profile_model → plan_scenarios → analyse_scenarios (+ Oumi Iris reviews each scenario) → [HITL approve scenarios] → find_public_data (for what the approved scenarios need) [HITL pick] → draft_spec (reference_sample or zero-shot) → generate_data → analyse_datasets → [HITL approve datasets] → run_tests (sandbox, one MLflow run per test) → analyse → critic (tries to overturn each finding) → report`. A LangGraph StateGraph fixes the order and gates; deep agents run the open-ended steps. Verdicts: `supports_compliance | indicates_gap | inconclusive | not_assessable_by_testing`. LLM = **Google Gemini only** (`GOOGLE_API_KEY`, `GEMINI_MODEL`); no OpenAI/Anthropic. Decision model = **Oumi Iris** (`pipeline/decision.py`, `POST https://inference.oumi.ai/v1/systemone`, `OUMI_API_KEY` + `OUMI_MODEL`) for the scenario review and the change judge, Gemini as fallback. Audit ids are readable: `<SYSTEM_ID>-<YYYYMMDD>-<HHMM>` (UTC).
- **Prompt engineering (mandatory for every agent/step prompt):** follow `docs/draft/prompt-engineering/prompt-engineering-optimization-plan.md` (the "Socratic agent loop": scope → define done → ask only when it pays → divide/delegate → alternatives where it matters → grounded verification (ἔλεγχος) → completion → limits/foresight; layered prompt architecture rules → agent instructions → defaults → user context → date with an explicit precedence statement; a sub-agent result contract; a verifier; short agent prompts; parameters not prose; Part 9 evaluation) and `docs/draft/prompt-engineering/Beyond Socrates Other Methods to Optimize an Agent's Prompts and Philosophy.pdf`. Written for magenticx; adapt it per pipeline step and to Gemini.
- **Regulation change:** Firecrawl monitor → RKS provision-level diff (`content_hash`) → LLM classifies change → `RegChange` + candidate `kb_version` → HITL accept → impact index (no LLM) → change judge per system (`no_impact | reinterpret_existing_evidence | rerun_tests | new_tests_needed`) → inbox + Telegram → re-run → delta report. Old decisions are marked `stale`, never rewritten.
- **Agent context = 4 sources, all files in a Postgres-backed virtual filesystem** (extends the agents service's `CompositeBackend`; tables `workspace_file_blobs`, `workspace_files` (versioned), `workspace_file_meta` (+pgvector), `workspace_events` (append-only audit, logs reads too)):
  - `/regulation/`: all regulation (AI Act, Omnibus, guidelines, FAQs, standards, national law, internal policies), read-only, pinned to the run's `kb_version`.
  - `/systems/<id>/`: the **system dossier** ("the folder"): `system-card.yaml`, `architecture.yaml`, docs, evidence, gaps.
  - `/systems/<id>/plugins/<name>/`: a **plugin** = configured connection to one model/endpoint: `plugin.yaml` (target card: access type `mlflow_model | rest | llm_chat | batch_file | dataset_only`, pipeline placement, I/O, expected behaviour, scenario hints; secrets only as `secret_ref`) + docs, `data/training-data.md`, `data/data-dictionary.yaml`, notes the engineer uploads at configuration. Drives scenarios, use cases and synthetic data.
  - `/memory/`: **agent memory per system** (agents service, `system_memories` in `agent_runtime`): `MEMORY.md` (derived index, injected into every step's prompt) + `audits/<audit_id>/<name>.md`; written with `remember` (forget is HITL-gated); every step and agent of every audit of the system shares it; **not user-visible**. A gate rejection's reason goes to the next run, which records the lesson.
- **Seed data:** dummy ML systems only, each a local MLflow model: SYS-001 CV Screener (Annex III 4(a), biased via postcode proxy), SYS-002 Credit Scorer (Annex III 5(b), nearly clean), SYS-003 Benefits Eligibility Triage. No chatbot, no seeded audits (the local database was reset to these three on 2026-11-15; refill with `POST /v1/admin/import-seed` after the `mlflow-seed` job).
- **Demo spine:** live test run with HITL gates → finding + critic → reject a test → the agent remembers the lesson → the next audit of the system is planned right, citing the memory entry → live regulation change (mirrored guideline page + Firecrawl "Check now") → Telegram alert → re-run → delta report. Langfuse shows every step.
- **Plugins (built 2026-11-15):** a plugin = the wrapper around one model (how the agent calls it: `access` mlflow_model `models:/<name>@champion` or rest `url`, `auth.secret_ref: env://NAME` only, limits, `io.output`, expected behaviour), saved as `plugins/<name>/plugin.yaml`, **hidden from the Folder tab**. Plugins tab = the system graph from `architecture.yaml` (Add a step / Add a model / Remove; click a model → plugin form with **defaults in grey** read from the graph + local MLflow: version, description, signature in/out). API: `GET /v1/systems/{id}/plugins`, `GET …/plugins/defaults?component=|model=|name=`, `PUT …/plugins/{name}` (`card`, `component`, `upstream`, `downstream`), `POST|DELETE …/plugins/components[/{id}]` (`mnamon/backend/{router,utils,schema}/plugins.py`, `tests/backend/test_plugins.py`; frontend `features/systems/components/detail_parts/{PluginsTab,PipelineGraph,PluginEditorSheet,GraphStepDialog}.tsx`, `lib/pluginForm.ts`). Start audit asks which plugin when there are 2+ (`data.target_plugin`).
- **Scenarios gate, partial approval (built 2026-11-15):** decision `approved` + `edits.approved_scenarios: [ids]` + `edits.excluded: {id: reason}` → only those go on (`gate_scenarios` → `_keep_approved` in `agents/pipeline/graph.py`); none approved = changes requested; an obligation with all scenarios excluded ends `inconclusive` with the reason. Gate UI with per-scenario checkboxes in `features/approvals` (check it was committed: `git log --oneline -15`).
- **Next (in order):** (1) click through Register → Classify → Approve and the scenario checklist in the browser; (2) demo video + submission by 18:00 Sun 15 Nov; (3) known red tests: frontend `routes.test` "/audits/aud-sys001-r2?view=findings", `graph.test` "step summaries" (Greek locale number format?), backend `test_async_tasks` one flaky test.
- **Open:** whether the Omnibus changed ex-Art. 10(5) (protected attributes in bias tests).

## Layout

- The product lives in its own folder named after the brand, `mnamon/` (*Mnamon*, `branding/brand.json`): one subfolder per service, each with its own Dockerfile, and a `docker-compose.yaml` in the product folder wrapping them.
- Root `pyproject.toml` + `uv.lock` hold **repo tooling only** (ruff, pytest, pre-commit); service dependencies live inside each service.
- `branding/brand.json` is the brand source of truth (name, semantic colour tokens light + dark, fonts, logos). Never hard-code brand values elsewhere; read them from there (`export_tokens.py` → CSS vars).
- `presentations/decks/<deck>/deck.yaml` → `presentations/build.py` → `presentations/dist/<deck>.pptx` (git-ignored). New layouts go in `LAYOUTS` + `RENDERERS` and the README table.
- `mnamon/` (the product folder, named after the brand) holds the services and `docker-compose.yaml`: `backend` (FastAPI, ported from mAgenticX's dialogue bridge), `agents` (port 8003, internal), `reg-memory` (port 8010, internal: downloads the AI Act + supporting documents into one versioned `/data` volume with text and diffs; `docs/services/reg-memory.md`, tests in `tests/reg_memory/`), `model-gateway` (port 8000, host 8200: seed models from MLflow as bearer-auth, rate-limited REST endpoints; every demo system is a local MLflow model, no chatbot; `docs/services/model-gateway.md`, tests in `tests/model_gateway/`), `mlflow` (tracking server + registry, host 5500, `mlflow` database on Postgres, `mlflow_artifacts` volume) and `mlflow-seed` (one-shot: synthetic data → train → register `sys-00X-*@champion`, idempotent by `seed_hash`; case dossiers in `mnamon/mlflow-seed/cases/`, answer keys in `_answer-key/`, exported to the `seed_cases` volume; `docs/services/mlflow.md`, tests in `tests/mlflow_seed/`), `sandbox` runner, `frontend` (Vite + React + Tailwind SPA served by nginx on host 8080, proxies `/api` → backend; design system in `src/shared/ui` (import from `@/shared/ui`, colours only via brand tokens), features in `src/features/<name>/{components,hooks,handlers,lib}`, thin `src/pages/*View.tsx`, mock mode `VITE_USE_MOCKS=true` with handlers auto-loaded from `src/shared/lib/mocks/handlers/`; checks `npm run typecheck|lint|test|build` in `mnamon/frontend/`; `docs/services/frontend.md`), Postgres, Redis and a self-hosted Langfuse.
- **Backend rules:** no login; callers are an anonymous `X-Client-Id` (UUID), and every conversation query is scoped by `client_id` (miss = 404). **Exception (deliberate, for now):** systems and audits (`/v1/systems`, `/v1/audits`) are not scoped by client id; the client id is still the actor of every write ([backend systems](docs/services/backend-systems.md)). Rate limiting + structured logging on every endpoint. Routers thin → `utils/` logic → `schema/` (import from leaf modules; the `__init__` barrels stay empty). All imports at module top. Schema changes: edit `core/database/models.py` + a new Alembic migration (`alembic check` must pass). One `requirements.txt` (runtime + tests). Backend tests live in `tests/backend/` (own `pytest.ini`, run with the backend venv: `mnamon\backend\.venv\Scripts\python -m pytest tests/backend`); docs live in the root `docs/`. The agents-service contract is `docs/contracts/agents-contract.md`; AG-UI is always the run protocol.
- Repo-level tests in `tests/`; docs in `docs/` (`guides/`, `architecture/`, `services/`, `contracts/`; index in `docs/README.md`); helper scripts in `scripts/` (bash + PowerShell pairs).
- Diagrams: `docs/architecture/diagrams/build.py` draws every diagram as SVG + PNG from `brand.json` (Pillow; headless Edge is blocked on this PC). Edit the shapes there, never the PNGs, and rebuild; check the PNGs by eye.

## Rules

- **Shell gotcha:** long bash heredocs with quotes fail in this harness; write patch scripts to the scratchpad and run them.
- **Commit on the go** (user decision 2026-11-14, many agents run in parallel): small Conventional Commits per finished piece, staging **only your own paths** (`git add <paths>`, never `git add -A` / `.`), retry if `.git/index.lock` is busy. **Commit message = one title line only**: no body, no Co-Authored-By or any other trailer/attribution. Shared files (compose, `.env.example`, CHANGELOG, READMEs, CI, CLAUDE.md) are committed by whoever finishes last touching them. **Never push, force, rebase or open PRs**; the user does all git remote work.
- Keep `scripts/*.sh` and `scripts/*.ps1` in sync: a change to one goes in the other.
- Tests must not call paid LLM APIs; mock provider clients.
- **One env file for everything:** repo-root `.env` (git-ignored) from `.env.example`, in compact sections (sponsor API keys and integrations first). Never add another `.env.example`; add every new variable to its section there. Secrets only in `.env`.
- Update `CHANGELOG.md` under `[Unreleased]` and the relevant `docs/` page with each change.
- **End-of-day reminder (hackathon, 14-15 Nov):** the user is working from a borrowed PC. Before they finish for the day, remind them to log out of everything: GitHub (`gh auth logout`), git credentials (Windows Credential Manager) and `git config user.name/email`, Docker, browser sessions and any other signed-in accounts. Also clear `.env` secrets and the cloned repos if they should not stay on this machine.
