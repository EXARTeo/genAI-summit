# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed

- Frontend shell restyled after magenticx: tinted app frame with the sidebar on it and the main content as a rounded, shadowed card that scrolls internally; 16rem / 4rem rail whose icons stay pinned while it collapses (labels fade in), active entry as a gliding teal pill with an inset ring, Search (⌘K) as a raised card at the top of the rail, logo-hover expand when collapsed; `SidebarExtra` slot for feature content (chat conversation list) in the rail.
- Backend: **old memory design removed**: the `memory:system:*`, `memory:org` and `memory:proposals` namespaces, `/v1/memory/...` routes and `POST /internal/audits/{id}/memory-proposals` are gone; an approval with a rejection only records the reason (no memory proposal, `memoryProposalPath` dropped); `/internal/audits/{id}/files` reads the system folder only; migration `0004_drop_memory_namespaces` deletes old `memory:*` rows (data only). Runs of a conversation scoped to a system/audit now send `system_id` / `audit_id` in the agents run context.
- Agents service: `harness/models/` (reasoning summaries) is now tracked; the root `.gitignore` rule `models/` had kept it out of git.
- Frontend: **agent memory is no longer shown** (System → Lessons, `applied MEM-…` chips, the memory side sheet, `features/memory/` and its mocks removed; the approval drawer keeps reason + comment without "save as memory" switches; spec provenance `memory` → `business_rule`); **Settings page removed** (theme stays in the top bar); **Add rule** appends to the plugin's `data/business-rules.md` as a new file version instead of writing a memory proposal; mock timestamps are shifted into the recent past (`mocks/time.ts`) and future timestamps never read "in x minutes".
- Frontend redesign: neutral surfaces (zinc) with one teal accent, amber only for "needs a human" and red/green only for verdicts (`branding/brand.json` palette); calmer motion (150-250 ms, no glows, gradients or blobs), 13-14 px type scale, tables for tabular data. New **Home** overview (decisions waiting, agents at work, recent findings, systems at risk, latest regulation change). **Memory is no longer a top-level page**: per-system lessons live in System → Lessons, org-wide rules in Settings → Organisation rules, and `applied MEM-…` chips open a side sheet. Audit run page reworked as an agent console (compact pipeline with durations and live state, step header, neutral sensitivity chart with amber proxies, calmer gate cards, CI number lines, verdict mix bar) and a decisive approval drawer (decision cards with consequences, reason chips, a submit button that names the action). `?step=` deep-links a step. `npm run shots` (Playwright) screenshots every route in dark and light at desktop and mobile into `product/frontend/.shots/`.
- `docs/architecture/agent-context.md`: design for the agent's context (reg-memory as the single source of regulation, system dossier, plugins = target card (model/endpoint access, pipeline placement, expected behaviour) + docs and training-data descriptions) and self-improving memory (per-system + general, human-approved, cited in traces), all as files in a Postgres-backed virtual filesystem (`workspace_files`, append-only `workspace_events` ledger).
- `docs/architecture/synthetic-data.md`: synthetic test-data design (LLM drafts a GenerationSpec from the plugin files, deterministic DAG sampler + rule checks build the data, counterfactual twins with proxy propagation, five validation gates, Data Card schema, proposed `data-dictionary.yaml` extensions, MVP cut).
- `docs/architecture/diagrams/`: containers, engineer pipeline, regulation-change, traceability and agent-context diagrams as SVG + PNG, generated from `brand.json` by `build.py` (Pillow, no browser); `scripts/build-diagrams.*`.
- `docs/` split into `guides/`, `architecture/`, `services/` and `contracts/` (index in `docs/README.md`); all repo references updated. `docs/architecture/README.md` now summarises the AI Act Governance Copilot design (MVP containers, engineer pipeline, regulation-change flow) and links the full design PDF, renamed to `docs/architecture/ai-act-governance-copilot.pdf`.

### Added

- **Public data first** for synthetic test data. Agents service `harness/tools/public_datasets/` (pure Python + httpx): `search_public_datasets` builds queries from the system card + data dictionary, searches OpenML (name/tag listing), UCI (search API), Hugging Face (Hub + datasets-server) and optionally Firecrawl (`FIRECRAWL_API_KEY`), scores each candidate deterministically (schema overlap with synonyms and type fit, protected/proxy fields, label, relevance, task, size, licence allow-list, recency; column mapping with value maps and age bins; gaps and flags), optional Gemini note (`GOOGLE_API_KEY`), writes `dataset-candidates.json/.md` and a `public_dataset_candidates` artifact; `fetch_public_dataset` only for an approved artifact: row/byte cap, PII columns dropped, `datasets/public/<slug>/{data.csv,mapping.yaml,datasheet.md,source.json}` stored through the new backend route `PUT /internal/audits/{id}/datasets/public/{slug}/{name}`. LangChain tool objects via `build_public_dataset_tools()` (not registered yet) and a CLI (`python -m harness.tools.public_datasets`). synthkit `generation.mode: reference_sample`: maps the reference onto the dictionary and fits categorical conditionals (Laplace) and empirical quantiles (`dist: empirical`) along the DAG, refuses unmappable or out-of-range fields (kept zero-shot), keeps rules and transforms; Data Card `reference` block (source, licence, sha256, fit report, `realism_vs_reference`) and the realism gate compares against the reference; zero-shot unchanged. Live run: SYS-002 → OpenML credit-g (0.75), SYS-003 → UCI Census Income / Adult (0.63), SYS-001 → no good match (zero-shot). Compose passes `FIRECRAWL_API_KEY` and `BACKEND_INTERNAL_URL` to the agents service. Tests: `tests/agents/test_public_datasets.py`, `tests/sandbox/test_synthkit_reference.py`, `tests/backend/test_internal_datasets.py`; docs: `docs/architecture/synthetic-data.md` § 2a, `docs/services/sandbox.md`, `docs/services/agents-service.md`, `docs/services/backend-systems.md`, `docs/architecture/agent-context.md`.

With `system_id` in the run context, `/memory/` is mounted (deepagents `StoreBackend`): `MEMORY.md` derived on every read (grouped by audit, newest first, writes ignored) and `audits/<audit_id>/<name>.md` entries (file-tool writes only into the run's own audit). `MEMORY.md` is injected into the prompt of the agent and every sub-agent; native tools `remember(name, summary, content)` (slugged, idempotent, never raises, cap `MEMORY_MAX_ENTRIES_PER_SYSTEM`=200) and `forget(name, audit_id?)` (HITL-gated), both reserved against MCP. New optional run-context keys `system_id`, `audit_id`, `step` (validated, inherited by async tasks); internal read-only `GET /internal/systems/{id}/memory`. Tests in `tests/agents/test_system_memory.py`; docs in `docs/services/agents-service.md` § Memory, `docs/architecture/agent-context.md` §4-5, `docs/contracts/agents-contract.md`.
