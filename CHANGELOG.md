## [Unreleased]

### Changed

- **Obligation-driven audit pipeline (plan 01, agents):** `load_context → pin → ground_obligations → … → run_inference → analyse_results → assess_obligations → critic → seal → report`. `pin` writes kb / dossier / config / the concrete MLflow model version / seeds to `audit.data.pins`; `ground_obligations` builds the obligation map (catalogue, Iris on borderline rows, the requirement list as fallback) and `audit.data.obligations` focuses an audit; every scenario names an obligation. Raw before analysis: `run_inference` saves hashed per-row predictions (MLflow run tagged `audit_id`, `kb_version`, `obligation_ids`), `analyse_results` computes the metrics from them with `synthkit metrics` and lets the analyst run its own code over the saved files (code flags mismatches); the generated dataset is saved once (sha256) instead of regenerated. `assess_obligations`: rule verdict from the org thresholds, a Gemini assessor, an independent Iris verdict (Gemini only when Iris is down); disagreement → `inconclusive` + needs human; citations validated against the pinned kb; documentary obligations → `not_assessable_by_testing` with dossier evidence present / missing. The critic gives grounds per verdict and an `overall`; `seal` adds severity by in-force date, gap ids `G-<SYS>-<nn>`, a sha256 hash chain and the one-verdict-per-obligation invariant, posts to `POST /internal/audits/{id}/findings` and keeps writing `finding` artifacts; the report appends an evidence register and a gap list. Docs: [agents pipeline](docs/services/agents-pipeline.md).
- **Audit hardening (agents):** sealed findings chain from a per-audit genesis hash (no cross-audit hash clash), a spec still invalid after the redo falls back to a code-built spec, rule ids never reuse the dictionary's, perturbations touch numeric fields only (synthkit too), reads retry a dropped backend connection, the report carries `gap_list`, `evidence_register`, `bias_fairness_markdown` and `annex_iv_markdown`, and a focused re-run writes its delta report at the end.
- **Every audit finishes (agents):** tool errors return to the agent as text (the `lookup_provision` crash on id-string children is fixed), a step's agent run is retried once, `draft_spec`'s fixed keys and categorical-only coverage cells are set by code, coverage failures name the cells and counts, and any unrecoverable node failure writes an incomplete-audit report and fails the audit with its stage (the checkpoint stays for a retry).
- **Seed cards:** SYS-001 and SYS-002 gain org thresholds for flip rate, accuracy gap, representation and edge-case handling (fewer inconclusive metrics); synthkit reads `group_share_gap` and `valid_edge_failure_rate` from the card.
- **Regulation change end to end (plan 01 S6):** accepting a RegChange (UI or Telegram) starts the agents' change judge in the background with every system's card and sealed findings; impact now runs through each system's obligation map at the new kb (`changed provisions ∩ applicable obligations`), Iris judges each affected system, `rerun_tests` / `new_tests_needed` start a **focused** audit (`data.obligations`, pinned to the new kb), old findings on the affected obligations are marked `stale` (status events, or `finding_status` artifacts), and a `delta_report` artifact (old → new verdict, metric deltas, law vs model changed) is written when the re-run finishes (`POST /changes/delta/{audit}` rewrites it). The inbox `judge` flag reads the judge's own state (`pending | running | done | failed`), so "no system affected" no longer shows as pending.
- **Firecrawl credits guarded:** reg-memory caches every Firecrawl answer on disk (`FIRECRAWL_CACHE_MINUTES`, default 360) and never sends a URL Firecrawl cannot reach (localhost, private IPs, Docker hosts such as the demo mirror).
- **Demo data is ML models only:** the simulated SYS-004 support chatbot is gone (its seed case, the gateway's `POST /v1/chat/sys-004` route and `utils/chatbot.py`, its tests, the sandbox self-check entry, the frontend mock and the doc sections). The demo systems are SYS-001 to SYS-003, each a local MLflow model; the gateway's `/health` lists no simulated endpoints. The Art. 50 requirements stay in the regulation corpus.
- CD deploys from `konstantinosmpouros/genai-summit-2026` with the built-in GITHUB_TOKEN only: images to the owner's GHCR, Portainer pulls `deploy/denis/docker-compose-denis.yaml` from `main` and re-pulls the `:main` images on the webhook; no personal token in GitHub, no deploy repo or branch.
